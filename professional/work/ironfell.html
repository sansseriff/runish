Ironfell

An editor for explaining science: one document that a person edits by hand and a language model edits through typed operations.

Live demo ↗GitHub ↗Design docs ↗

Scientific papers and slide decks are poor at showing how a system actually behaves. Ironfell is a tool for building explanations that move and respond: a laser feeding a fiber into a power meter, a pendulum you can drag by either end, a thermal network that re-solves as you change it.

The core is a document format designed to be edited by two authors at once. A person manipulates shapes directly on a GPU canvas; a language model reads compact views of the same document and writes back declarative edits. Both go through the same transactional operation log, so either can undo the other and neither silently overwrites the other’s work.

The architecture separates what a person authored from everything derived from it. Resolved transforms, solved constraint poses, signal values, spatial indexes and pixels are all rebuildable caches. That separation is what makes exact undo, cheap invalidation and a renderer-independent file format possible.

The design is written up in ten vision documents and a set of implementation specs, each with exit criteria and dated completion notes. They cover what a mouse is for when language models can author scenes, the three kinds of time in an animation system, and how entities, compositions and ports keep many representations of one apparatus consistent.

Highlights

  • An identity-stable document store where every change is an invertible operation, so undo, rendering and the language model all read one operation log.
  • One thing, many pictures: a modulator can appear in a schematic, a 3D assembly and a cartoon, linked through a shared entity with typed ports that carry values with units.
  • A constraint solver (projected Levenberg–Marquardt) that lets you grab any part of a mechanism and have the rest follow; a 12-variable solve takes 280 µs natively.
  • Rendering work driven by measurement: a 100,000-shape composition idles with 2 engine entities, and rotating a 10,000-shape group went from 67 to 27 ms per frame.
  • A native macOS target through Tauri that shares the engine and UI with the web build, verified with 100,000 simulated runtime entities.
  • About 145,000 words of design documents, from the ontology (model, projection, annotation) down to frame scheduling.
